# 点餐宝数据归档规则

## 目标粒度

网页中的一个推荐数据点必须是能够独立构成一餐的主菜、主食成品或套餐。米饭、口味、酱料、锅底、赠品、单份小料、辅料、餐具、药品、日用品和其他非餐饮商品不能成为推荐项。

## 判断顺序

1. 清除营销前缀、装饰符号和括号规格说明，但保留私有原始订单不变。
2. 对现有历史唯一条目逐项审阅，使用精确目录记录“保留/排除”，不使用模糊包含匹配代替人工判断。
3. 对未来首次出现的条目，以整张订单为上下文，综合餐厅类型、同单是否存在更强主菜、份量描述、菜品语义和名称完整度评分。
4. 对保留主菜汇总历史下单时间。早餐语义明确的菜品优先归入早餐，其余以时段占优分布判断；并列时使用历史中位下单小时。
5. 对可独立成餐的条目建立规范菜名：相同清洗名称跨日期、跨分店直接归并；确认过的别名通过精确映射归并。禁止仅凭模糊相似度自动合并。
6. 公开数据只保留通过归档的主菜，并为每个规范菜品写入稳定 `dishId` 和 `mealPeriod`。前端随机池按 `dishId` 再去重，因此同一菜多次下单只占一个候选。

## 自动化检查

- 公开数据禁止出现地址、收件人、电话、订单号、Cookie 或 Token。
- 每个公开菜品必须有稳定 `dishId` 和合法餐段。
- 同一规范菜名只能生成一个 `dishId`；不同日期、不同分店和确认别名必须复用该 ID。
- 已审阅的米饭、口味、餐具、药品和非餐饮商品不得重新进入推荐池。
- 未见过的新菜品必须通过订单级上下文评分，并在审计文件中标记为 `inferred`。
- 新别名只有经过订单上下文确认后才能加入精确映射，禁止自动接受模糊相似名称。
