# 点餐宝 — 产品需求文档（PRD）

> 版本：v1 · 2026-07-14 · 基于美团外卖历史订单的选餐助手

---

## 一、产品概述

### 1.1 背景
用户日常用餐有选择困难，希望通过历史点餐数据建立一个个人化的选餐数据库，支持随机挑选和条件筛选，快速决策「今天吃什么」。

### 1.2 目标
开发一个可部署到 GitHub Pages 的个人静态网页应用，利用美团外卖历史订单数据，提供按地点筛选和随机选餐功能，帮助用户在 30 秒内完成用餐决策。无需云服务器；原始订单只保留在本机，网页只读取脱敏后的公开数据。

### 1.3 用户画像
- 上海徐汇区上班族
- 川湘菜爱好者
- 单人用餐为主，客单价 ¥20-¥90
- 日常纠结「吃什么」

## 二、功能需求

### 2.1 核心功能（P0）

#### F1. 随机选餐
- **🎲 换一个**：从已归档的独立主菜中随机出一道（含餐厅信息）
- 展示内容：菜品名、餐厅名、上次点的日期、地点标签
- 支持「换一个」重新随机

#### F2. 按条件筛选 + 随机
- 首页只展示一个地点分段按钮：
  - **家（徐汇电影华苑）**
  - **新天地（徕卡办公室）**
- 默认选中上次使用的地点；首次使用默认选中「家」
- 提供早饭、午饭、晚饭三个餐段按钮，只从对应餐段的归档主菜中随机
- 本地更新脚本根据原始收件地址映射地点，网页只接收 `locationCode` 和 `locationLabel`
- 具体收件地址不得出现在页面、公开 JSON、浏览器日志或前端缓存中
- 餐厅、菜系、日期范围放入折叠的「更多筛选」，不在首页首屏展开
- 不提供预算按钮或价格区间筛选
- 筛选后点击随机 → 从符合条件的菜品中随机出

#### F3. 数据看板
- **常去餐厅 TOP10**：条形图/列表（点单次数 + 消费金额）
- **最爱菜品 TOP10**：点单频率排行
- **月度消费趋势**：每月总消费金额折线/柱状图
- **本周吃了啥**：本周点餐日历视图

### 2.2 辅助功能（P1）

#### F4. 快速决策模式
- **「不纠结」模式**：连续随机 3 道菜，三选一
- **「今日限定」**：只从最近 30 天点过的餐厅中随机
- **「换个口味」**：排除最近 3 次吃过的餐厅

#### F5. 历史查询
- 按日期查看历史点餐记录
- 按餐厅查看所有点过的菜品
- 搜索框（菜品名/餐厅名）

#### F6. 数据管理
- 手动添加/编辑订单（应对非美团渠道的用餐记录）
- 导入/导出 JSON 数据
- 数据版本历史

### 2.3 增强功能（P2）

#### F7. 地点候选扩展
- 可为每个地点维护一份公开的常用餐厅候选清单
- 不接入需要暴露地址、坐标或密钥的地图 API
- 与历史订单一起参与随机推荐

#### F8. 统计洞察
- 外卖消费月账单
- 口味偏好分析雷达图
- 点餐时间分布（早餐/午餐/晚餐/夜宵占比）

## 三、技术方案

### 3.1 架构设计

```
本机：美团采集 → 私有原始订单 → 主菜归档/餐段推理/脱敏 → 公开 JSON
                                                   ↓ git push
GitHub Pages：React 静态网页 ← 只读取脱敏公开 JSON
```

### 3.2 技术选型

| 模块 | 技术 | 理由 |
|:----|:-----|:-----|
| 前端 | React 19 + Vite | 静态构建，适配 GitHub Pages |
| 样式 | 原生 CSS | 控制依赖，保持界面简洁 |
| 数据更新 | Python 本地脚本 | 复用美团采集并在本机完成脱敏 |
| 运行时存储 | 静态 JSON + LocalStorage | 无需服务器；保存地点与餐段偏好 |
| 图标 | Phosphor Icons | 接近选定设计的线性图标风格 |
| 部署 | GitHub Pages + Actions | 推送后自动构建发布 |

### 3.3 数据流

```
美团采集脚本
    ↓ 本机私有保存、校验、地址映射
.private/orders.raw.json (私有 SSOT)
    ↓ update_site_data.py + dish_intelligence.py 归档、餐段推理、脱敏
web/public/data/orders.public.json
    ↓ GitHub Pages 静态加载
React 前端渲染
```

### 3.4 页面布局

```

│  今天吃什么？                     │

│  [ 早饭 ] [ 午饭 ] [ 晚饭 ]        │
```

### 3.5 地点映射与隐私

| locationCode | 前端显示 | 本机映射依据 |
|:-------------|:---------|:-------------|
| `home_xuhui` | 家（徐汇电影华苑） | 私有原始收件地址规则 |
| `office_xintiandi` | 新天地（徕卡办公室） | 私有原始收件地址规则 |

- 精确映射可以写入 `.private/location-map.json`，该目录被 Git 忽略。
- 公开数据只包含地点代码与显示标签。
- 无法识别的地址映射为 `other`，前端显示「其他地点」，不得回退展示原地址。

## 七、约束与边界

### 7.1 不做（Scope Out）
- ❌ 不接入美团实时 API（在本机采集后生成脱敏静态数据）
- ❌ 不做多人协作/分享功能
- ❌ 不做推荐算法/机器学习（纯随机 + 筛选）
- ❌ 不在公开数据或网页中存储、传输或展示具体收件地址
- ❌ 不使用云服务器或运行时后端

### 7.2 已知风险
- ⚠️ 历史数据可能包含非食品类订单（药品、日用品）→ 通过菜系归类过滤
- ✅ 菜品名中的营销标签、装饰符号和括号规格说明 → 已在公开数据生成时统一清除
- ⚠️ 同一菜品在不同餐厅的命名不一致 → 暂不做菜品去重合并
- ⚠️ 美团反爬策略可能变化 → 数据更新脚本需同步维护
